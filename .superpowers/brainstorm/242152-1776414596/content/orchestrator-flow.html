Comment Claude Code sépare naturellement ce qui est visible et ce qui est technique

BACKEND NODE.JS (port 8080)
• Sert le chat UI (HTML/CSS/JS)
• WebSocket ↔ navigateur
• Lance Claude Code via SDK
• Filtre : passe uniquement les textes de l'orchestrateur
• Ignore les tool calls (technique)

CLAUDE CODE SDK
🎯 Orchestrateur (nouveau agent)
Instruction clé dans son system prompt :
"Tu parles à un non-technicien. Jamais de noms de fichiers, jamais de code dans tes messages. Décris les actions en français simple."
👨‍💻
developer
modifie les fichiers
🔍
reviewer
vérifie le code
📝
documenter
documente
↑ Ces agents opèrent en sous-contexte — leur output technique reste invisible au user
Pourquoi ça tient : quand l'orchestrateur dispatch un Task("developer", ...), le résultat du developer revient dans le contexte interne de l'orchestrateur — pas en texte visible. L'orchestrateur CHOISIT ensuite ce qu'il dit à l'utilisateur. On lui impose de ne jamais exposer les détails techniques.
Ce que le SDK permet de filtrer
❌ On ignore (tool calls)
tool_use: Read { path: "src/..." }
tool_use: Edit { file: "Deal.ts" ... }
tool_use: Task { agent: "developer" }
tool_result: { verdict: "APPROVED" }
✅ On affiche (texte orchestrateur)
"Je demande à mon développeur d'ajouter le champ..."
"Le code est en cours de vérification..."
"✅ C'est fait ! Budget est maintenant disponible."
